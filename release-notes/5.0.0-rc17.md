# Svelte Treeview 5.0.0-rc17 — Release Notes

**Released:** 2026-11-22 · **Pre-release** (`npm install @keenmate/svelte-treeview@rc`)

These notes cover the changes since **5.0.0-rc16**, the last version on npm.

This rc moves three more pieces onto `@keenmate/web-components-core`, so they behave exactly
like web-treeview's: the **context menu** (core `openMenu()`), the **labels** (core `/locale`,
flat keys, a page-wide dictionary) and the **icons** (core `renderIcon`). The label keys and the
context-menu CSS classes are renamed. It also fixes the published types for
`moduleResolution: node16 / nodenext` (#30) and ships the fixes from a whole-library review.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/Keenmate/svelte-treeview/blob/prod/CHANGELOG.md) (section
5.0.0-rc17); this document is the upgrade guide and the highlights.

      ([table](#context-menu-classes-are-cores))

## Breaking changes

### Label keys are flat `<elementType>.<name>` names

The `labels` prop takes web-treeview's keys — short (`messages.noData`) or full
(`svelte-treeview.messages.noData`).

| rc16 | rc17 |
|---|---|
| `noData`, `noResults`, `dropHere` | `messages.noData`, `messages.noResults`, `messages.dropHere` |
| `noDisplayValue` | `labels.noDisplayValue` |
| `loading`, `showFullLabel` | `ariaLabels.loading`, `ariaLabels.showFullLabel` |
| `copy` … `sortAll` (13 menu built-ins) | `menuItems.copy` … `menuItems.sortAll` |

```svelte
<!-- rc16 -->
<Tree labels={{ noData: 'Nothing here', copy: 'Kopírovat' }} … />
<!-- rc17 -->
<Tree labels={{ 'messages.noData': 'Nothing here', 'menuItems.copy': 'Kopírovat' }} … />
```

### Context-menu classes are core's

The menu is core `openMenu()`, so it carries core's markup.

| rc16 | rc17 |
|---|---|
| `.stv__context-menu` | `.km-menu` (root; `.km-menu--custom` for a `contextMenu` snippet) |
| `.stv__context-submenu` | `.km-menu--submenu` — a sibling level, no longer nested in its parent |
| `.stv__context-menu-item` (`--disabled`, `--danger`, `--toggled`) | `.km-menu__item` (same modifiers) |
| `.stv__context-menu-item--has-children` | `.km-menu__item--has-submenu` |
| `.stv__context-menu-icon` / `-label` / `-shortcut` | `.km-menu__icon` / `__label` / `__shortcut` |
| `.stv__context-menu-divider` + `-divider-label` | `.km-menu__divider` (`--named`, the text inside) |
| `.stv__context-menu-arrow` | — (core's stylesheet draws the arrow) |

`ContextMenuItem` / `ContextMenuDivider` (the snippet components) emit the same `km-menu__*`
markup. A class-list item icon renders as `<i class="fa-solid fa-star">` (no `stv__icon`), as
core's menu does.

### Context-menu variables fall through to page-wide ones

The `--stv-context-menu-*` names are unchanged, but they no longer carry svelte-treeview defaults:
each maps onto core's private `--_km-menu-*`, so a value resolves this tree's
`--stv-context-menu-*` → the page-wide `--km-menu-*` → `--base-*` → core's default. The unstyled
menu now looks like web-treeview's (core's defaults). New: `--stv-context-menu-arrow-font-size`.

### Node icon markup

The node icon is a `<span class="stv__node-icon">` wrapper with core `renderIcon`'s markup inside
(was `<i class="stv__node-icon {value}">`). A class list (`fa-solid fa-folder`) is an inner
`<i class="stv__icon fa-solid fa-folder">`; the new `.stv__icon` rule sizes it from the wrapper.
The `icon` snippet still wins over all of it.

## Behaviour changes

### The context menu is a bottom sheet on a phone

`menuPresentation` defaults to `'auto'`: a bottom sheet on a phone (core's device class), the
floating menu on a tablet / desktop. `'floating'`, `'sheet'` or `'drawer'` (with `menuSide`)
fix it.

### The context menu keyboard

Arrows / Home / End move through the enabled items, → / ← open and close submenus, Enter / Space
run the item, Escape closes one level, Tab leaves, and an item's `shortcut` runs it while the menu
is open. Shift+F10 / the ContextMenu key open the focused node's menu with its first item focused;
closing returns focus to the tree. A `contextMenu` snippet menu gets Escape / Tab only (core's rule
for custom menus).

### Context-menu dismiss

The menu closes on an outside press, a scroll that moves the tree (never one inside the menu or a
bare wheel), window blur, or another Keenmate overlay opening — it used to close on any scroll or
wheel on the page.

### Icons are resolved in a fixed order

An icon value is markup → a core built-in name → `renderIconCallback` → the page-wide hook → an
icon font → text. A value that is a built-in name (`close`, `check`, `user`, …) now renders core's
masked glyph and never reaches a hook. On SSR the icons render without hooks; the client renders
them once the tree is mounted.

## New features

### Page-wide labels and translation callbacks

```js
window.components.locale = {
  labels: { 'svelte-treeview.messages.noData': 'Žádná data', 'svelte-treeview.menuItems.copy': 'Kopírovat' },
  translateCallback: ({ component, key, template, params, locale }) => myI18n(key, params) ?? null
};
```

One flat dictionary of full keys for every Keenmate component on the page; assigning a new object
(or `null`) re-renders every live tree. Per key: `labels` prop → the tree's `translateCallback` →
the page-wide `translateCallback` → the page dictionary → English. The floating drop pads are
labels now (`labels.dropBefore` / `dropAfter` / `dropChild`).

### Your own icon names: `renderIconCallback`

```svelte
<Tree renderIconCallback={(name, ctx) => name.startsWith('my-') ? mySvg(name) : null} … />
```

`ctx` = `{ component: 'svelte-treeview', element, prefix: 'stv', node, controller, …render state }`
(`item` instead of `node` for a context-menu item). `null` passes to the page-wide
`window.components.renderIconCallback`.

### Context menu: shortcuts, lazy submenus, sheet

Shortcuts are shown formatted for the platform (`Ctrl+K`, `⌘K` on a Mac). A lazy
`getChildrenCallback` submenu shows a loading row (`messages.loading`) until it resolves. The phone
sheet is titled with the node's text, with a Back row for submenus (`menuItems.back`) and a close
button (`ariaLabels.closeSheet`).

## Fixes

- Types under `moduleResolution: node16` / `nodenext` ([#30](https://github.com/Keenmate/svelte-treeview/issues/30)): `TreeController`, `LTreeNode`, `Ltree` and their types were `any`.
- Edits while a search filter is active changed the filtered copy, not the real tree — a node deleted while searching came back. Selection / focus made while filtered was lost when the filter cleared.
- Pasting a subtree of three or more levels with an id-minting `nodeInputTransformationCallback` dropped every grandchild.
- `uncheckAll()` and assigning `checkedPaths` left an indeterminate `[-]` branch; a cascade over three or more levels left a middle branch `[-]`.
- A runtime `labels.noDisplayValue` change never reached the rows; a node with a missing display field rendered an empty label.
- Assigning `expandedPaths` left a visible row's expand arrow in the old state.
- The context menu opened at twice the offset; named-key item shortcuts (`F2`, `Del`) never fired; Escape didn't close a snippet menu.
- Keys typed into an `<input>` inside a row triggered tree shortcuts and navigation.
- Pointer drag: a refused or vetoed drop now restores the selection; a one-entry `beforeDragStartCallback` manifest ignored its holes; the drag ghost rendered unstyled.
- Search never built its index on Safari (no `requestIdleCallback`).
- `insertResult` counted a duplicate path as successful; `statistics.nodeCount` / `filteredNodeCount` were off.

The full list is in the CHANGELOG ("Fixed — code review batch").
