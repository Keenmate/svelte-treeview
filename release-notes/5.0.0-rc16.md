# Svelte Treeview 5.0.0-rc16 — Release Notes

**Released:** 2026-11-17 · **Pre-release** (`npm install @keenmate/svelte-treeview@rc`)

These notes cover the changes since **5.0.0-rc15**, the last version on npm. A `5.0.0` section
in the CHANGELOG was never published (its old `[PUBLISHED]` tag was a mistake); its changes are
folded in here.

This rc is **breaking, with no aliases.** svelte-treeview takes `@keenmate/web-treeview`'s API
and vocabulary, so the two packages read the same: the click set is *selected* and the checkbox
set *checked*, every callback takes one ctx object, the context menu uses the Keenmate core
action model, and the CSS tokens are one list with web-treeview's. It also drops the recursive
renderer, adds row animation on expand / collapse, and moves logging and dark mode onto the
Keenmate core logger and theme context. Code written for rc15 needs updating: the old names are
gone, not deprecated.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/Keenmate/svelte-treeview/blob/prod/CHANGELOG.md) (section
5.0.0-rc16); this document is the upgrade guide and the highlights.

## Upgrade checklist

Do the selection rename **first, and checkbox before click**: rc15's `selectNode` was the
checkbox call; in rc16 the same name is the click call. Renaming in the other order turns your
checkbox code into click-selection code without a compile error.

**Everyone**

- [ ] Rename the checkbox set: `selectedPaths` → `checkedPaths`, `selectNode` / `selectNodes` /
      `selectAll` / `deselectNode` → `checkNode` / `checkNodes` / `checkAll` / `uncheckNode`,
      `onSelectionChange` → `onCheckedChange`, … ([table](#selected-and-checked-replace-highlighted-and-selected))
- [ ] Then rename the click set: `highlightedPaths` → `selectedPaths`, `highlightNode` →
      `selectNode`, `onHighlightChange` → `onSelectionChange`, `highlightedNodeClass` →

- [ ] Rename `data` → `nodes`; replace `getAllData()` with `bind:nodes` or `controller.nodes`.
      ([details](#data-is-now-nodes))
- [ ] Rename the props in the [renamed props table](#props-renamed) (`searchText` → `searchTerm`,
      `shouldShowCheckboxes` → `isCheckboxesShown`, `isProgressiveRender` →
      `isProgressiveRenderEnabled`, `virtualRowHeight` → `virtualScrollItemHeight`, …).
- [ ] Replace `noDataText` / `displayValueFallback` with `labels={{ noData, noDisplayValue }}`.
      ([details](#labels-replace-nodatatext-and-displayvaluefallback))
- [ ] Remove `isFlatRenderingEnabled`, `shouldDisplayDebugInformation`,

## Breaking changes

### Selected and checked replace highlighted and selected

The two sets get web-treeview's names, and the `--base-selected-*` tokens they paint with: the
click / Ctrl / Shift set is **selected**, the checkbox set is **checked**. "Highlight" now means
only visual emphasis (the `scrollToPath` flash, the drag-over highlight). Both sets are renamed,
so one name moved from one set to the other — do the checkbox rename first.

Checkbox set:

| rc15 | rc16 |
|---|---|
| `selectedPaths` | `checkedPaths` |
| `selectNode` / `selectNodes` / `selectAll` | `checkNode` / `checkNodes` / `checkAll` |
| `deselectNode` | `uncheckNode` (new: `uncheckNodes(paths)`) |
| `clearSelection(paths?)` | `uncheckAll()` (paths form → `uncheckNodes`) |
| `getSelectedNodes` / `isNodeSelected` | `getCheckedNodes` / `isNodeChecked` |
| `isSelectedMember` / `getIsSelectedCallback` | `isCheckedMember` / `getIsCheckedCallback` |
| `cascadeSelectPolicy` / `CascadeSelectPolicy` | `cascadeCheckPolicy` / `CascadeCheckPolicy` |
| `onSelectionChange` | `onCheckedChange` |
| `LTreeNode.isSelected` | `isChecked` |
| `VisualState` `selected` / `notSelected` | `checked` / `unchecked` |
| `NodeRenderContext.isSelected` | `isChecked` |

Click set:

| rc15 | rc16 |
|---|---|
| `highlightedPaths` | `selectedPaths` |
| `highlightNode` / `highlightNodes` / `highlightAll` | `selectNode` / `selectNodes` / `selectAll` |
| `clearHighlight` | `clearSelection` |
| `getHighlightedNodes` / `isNodeHighlighted` | `getSelectedNodes` / `isNodeSelected` |
| `onHighlightChange` | `onSelectionChange` |
| `highlightedNodeClass` | `selectedNodeClass` |
| `HighlightMode` | `SelectMode` (`SelectionMode` stays the `single` / `multiple` knob) |
| `LTreeNode.isHighlighted` | `isSelected` |
| `NodeRenderContext.isHighlighted` | `isSelected` |
| `toggleFocusedHighlight`, `navHighlight*` | `toggleFocusedSelect`, `navSelect*` |
| keydown ctx `highlightedNodes` | `selectedNodes` |

New: `checkedNodeClass`, a class for checked rows (they have no default row style; the checkbox
is the signal).

### Data is now nodes

`data` → `nodes` on `<Tree>`, `<TreeProvider>`, `update()` and `TreeController`, and
`getAllData()` is removed. `nodes` is the input **and** the current state: after a move, add,
remove, paste, `applyChanges` or branch operation the tree writes its data back, so `bind:nodes`
always holds what the user sees. The write-back is coalesced on a microtask (`await tick()`
before reading right after a call; `controller.nodes` is synchronous) and is not re-inserted,
so expand and selection state survive. Assigning a new array still reloads the tree.

```svelte
<!-- rc15 -->
<Tree data={items} … />   …   const current = tree.getAllData();
<!-- rc16 -->
<Tree bind:nodes={items} … />   …   // items is the current data
```

### Props renamed

| rc15 | rc16 |
|---|---|
| `data` | `nodes` |
| `searchText` | `searchTerm` |
| `isProgressiveRender` | `isProgressiveRenderEnabled` |
| `isAccordionExpand` | `shouldExpandAsAccordion` |
| `shouldShowCheckboxes` | `isCheckboxesShown` |
| `shouldShowNodeTooltips` | `isNodeTooltipsShown` |
| `shouldShowDropPlaceholderWhenEmpty` | `isEmptyDropPlaceholderShown` |
| `shouldEnableTreeDropZone` | `isTreeDropZoneEnabled` |
| `tooltipFollowCursor` | `shouldTooltipFollowCursor` |
| `virtualRowHeight` / `virtualOverscan` / `virtualContainerHeight` | `virtualScrollItemHeight` / `virtualScrollOverscan` / `virtualScrollContainerHeight` |
| `selectionMode: 'multi'` | `selectionMode: 'multiple'` |
| `nodeClass` / `nodeContentClass` | `getNodeClassCallback` / `getNodeContentClassCallback` |
| `onTreeKeydown` | `beforeKeydownCallback` (return inverted) |
| `dropZoneLayout: 'above' \| 'below'` | `'before' \| 'after'` (classes `.stv__drop-zones--before` / `--after`) |

The names follow web-treeview and the shared naming rules: booleans start with `is` / `should`,
a search string is a `term`, virtual-scroll settings are one `virtualScroll*` family.

### Labels replace noDataText and displayValueFallback

```svelte
<!-- rc15 -->
<Tree noDataText="Nothing here" displayValueFallback="?" … />
<!-- rc16 -->
<Tree labels={{ noData: 'Nothing here', noDisplayValue: '?' }} … />
```

`labels` merges per key over the English defaults: `noData`, `noResults` (new: the search
matched nothing — the empty state now tells it from "no nodes"), `dropHere`, `noDisplayValue`,
`loading`, the 13 built-in menu texts and `showFullLabel`. `''` renders nothing. Exports:
`resolveLabel`, `DEFAULT_LABELS`, `TreeLabels`.

### Every callback takes one ctx object

Positional arguments are gone, so fields can be added later without breaking anyone. Every ctx
also carries `controller` (non-enumerable: destructuring works, a spread or `JSON.stringify`
skips it).

| rc15 | rc16 |
|---|---|
| `getIsDraggableCallback(node)` and every other per-node `get*Callback(node)` | `get…Callback({ node })` |
| `nodeClass(node)` / `nodeContentClass(node)` | `getNodeClassCallback({ node })` / `getNodeContentClassCallback({ node })` |
| `sortCallback(items)` | `sortCallback({ nodes })` |
| `beforeCheckboxToggleCallback(node, checked, affectedPaths)` | `beforeCheckboxToggleCallback({ node, isChecked, affectedPaths })` |
| `nodeOutputTransformationCallback(data, ctx)` / `nodeInputTransformationCallback(data, ctx)` / the `transform` of `pasteNodes` / `duplicateNodes` | `(ctx)` with `ctx.data`; transform ctx `index` → `rootIndex` |
| `copyNodeWithDescendants(…, transformData(data, node))` | `transformData({ data, node })` |
| `onContainerResize(size, deviceClass)` | `onContainerResize({ size, deviceClass })` |
| `applyChanges` result `failed[].index` | `failed[].changeIndex` |

### onTreeKeydown is beforeKeydownCallback, return inverted

It is an interceptor, so it follows the `before*Callback` contract: return `false` to suppress
the tree's keyboard handling, nothing to let it run. rc15 suppressed on `true`. It is
synchronous — a returned Promise is ignored with a warning. The ctx is unchanged:
`{ event, focusedNode, selectedNodes, controller }`.

### Events and methods renamed

| rc15 | rc16 |
|---|---|
| `onCopy` / `onCut` / `onPaste` / `onDelete` | `onNodeCopy` / `onNodeCut` / `onNodePaste` / `onNodeDelete` |
| `onNodeDragDenied` / `onNodeDropDenied` | `onNodeDragReject` / `onNodeDropReject` |
| `insertBranch(parentPath, rows)` | `addBranch(parentPath, rows)` (new `insertBranch(targetPath, rows, position)` is positioned) |
| `deleteBranch` / `DeleteBranchResult` | `removeBranch` / `RemoveBranchResult` (`removedCount` → `count`) |
| controller `deleteNodes(paths?)` | `runDeleteCommand(paths?)` (the user Delete: veto + `onNodeDelete`); new `removeNodes(paths)` = programmatic, no veto, no event |
| `nodeRef(nodeOrPath)` | `getNodeRef(nodeOrPath)` |
| `getNodeIsDropAllowed(node)` | `isNodeDropAllowed(path)` |
| `openContextMenu(node, x, y)` | `openContextMenu(path, x, y)` |
| `DEFAULT_TREE_LABELS` | `DEFAULT_LABELS` |
| environment option `immediate`, types `ObserveOptions` / `PointerType` | `shouldFireImmediately`, `ObserveEnvironmentOptions` / `PointerAccuracy` |

### Silent is isSilent

Every options object says `isSilent` (selection, checked, focus mutators, `ExpandOptions`,
`SortOptions`). The expand options are `ExpandOptions { isExclusive?, isSilent? }` (were
`{ exclusive?, noEmit? }`). `isSilent` skips the change callbacks **only** — the tree always
re-renders and the bound props still update. In rc15 a silent `expandNodes` also skipped the
re-render, so the change didn't show.

### Set paths methods removed

`setSelectedPaths`, `setCheckedPaths`, `setExpandedPaths` and `getExpandedPaths` are gone from
`<Tree>` and `TreeController`. Assign the bindable instead — it replaces the whole set silently,
like any bound prop:

```svelte
<Tree bind:selectedPaths bind:checkedPaths bind:expandedPaths … />
<script>
  selectedPaths = new Set(['1.2', '1.3']);   // was tree.setSelectedPaths([...])
</script>
```

Additive, event-firing changes stay `selectNodes` / `clearSelection` / `checkNodes` /
`uncheckAll` / `expandNodes`.

### scrollToPath takes web-treeview's options

```ts
// rc15
tree.scrollToPath(path, { expand: true, highlight: true, scrollOptions: { block: 'center' }, containerScroll: true });
// rc16
tree.scrollToPath(path, { shouldExpandAncestors: true, shouldHighlight: true, block: 'center' });
```

`ScrollToPathOptions = { shouldExpandAncestors = true, shouldHighlight = false, behavior, block,
inline }`. The flash is now **off** by default (`highlight` defaulted to `true`). Removed:
`expand`, `expandTarget`, `highlight`, `scrollOptions`, `containerScroll`, `containerElement`.

### Mutation vocabulary add insert update remove

`applyChanges` operations: `'create'` → `'add'` `{ parentPath, data, pathSegment? }`,
`'delete'` → `'remove'` `{ path }`, new `'insert'` `{ targetPath, position, data }`. New
`insertNode(targetPath, data, position)` places one node before / after / inside a target.
Same vocabulary as web-treeview: *add* appends under a parent, *insert* places at a position,
*remove* is programmatic.

### Context menu uses the core action model

The menu is web-treeview's, built on Keenmate core actions:

```ts
// rc15
getContextMenuItemsCallback={(node, closeMenu, selectedNodes) => [
  { label: 'Rename', onclick: () => { rename(node); closeMenu(); }, className: 'x' },
  { divider: true, label: 'More' },
]}
// rc16
getContextMenuItemsCallback={(ctx) => [
  { id: 'rename', text: 'Rename', onClick: (detail) => rename(detail.node), cssClass: 'x' },
  createMenuDivider('More'),
  'copy', 'paste', 'delete',          // built-in actions
]}
```

- The ctx is `TreeMenuContext { node, path, parent, siblings, controller }`. Read the selection
  with `ctx.controller.getSelectedNodes()`; items close the menu themselves (`shouldCloseOnClick`,
  default `true`) or via `ctx.controller.closeContextMenu()`.
- Item fields: `label` → `text`, `onclick` → `onClick(detail)`, `className` → `cssClass`; new
  `isDanger`, `isToggled`, `tooltip`, `shortcut`, `children`, `get*Callback(ctx)`.
- Built-in actions by name: `copy cut paste delete expand collapse expand-subtree
  collapse-subtree expand-all collapse-all sort sort-subtree sort-all` — texts from `labels`,
  acting on the selection when the clicked node is in it.
- Order: `beforeActionCallback` (`false` cancels) → item `onClick` → built-in → `onAction`.
- Types: `ContextMenuContext` / `ContextMenuItem` / `ContextMenuDivider` / `ContextMenuEntry` →
  `TreeMenuContext` / `TreeMenuItem` / `MenuDivider` / `TreeMenuEntry`. The snippet components
  take the same names (`<ContextMenuItemC text onClick cssClass>`, `<ContextMenuDividerC text>`).

### Props and exports removed

| Removed | Use instead |
|---|---|
| `isFlatRenderingEnabled` | nothing — flat is the only renderer ([details](#one-flat-renderer)) |
| `shouldDisplayDebugInformation`, `shouldDisplayContextMenuInDebugMode` | the loggers; `controller.statistics` |
| `expandIconClass` / `collapseIconClass` | `iconSet` + `toggleIconMode` |

| `TreeController` internals (`on*Handler`, `vs*`, `flat*`, `startDrag`, `dropAt`, …) | the props / `update()`; they are `@internal` and no longer in the published types |

### One flat renderer

The recursive renderer is gone; rows are always siblings under `.stv__tree` (plain, with
`isProgressiveRenderEnabled`, or with `isVirtualScrollEnabled`). CSS that targeted
`.stv__children` or nested rows needs to target `.stv__node` by level instead (`data-tree-path`,
the indent is per row). `onRenderStart` / `onRenderProgress` / `onRenderComplete` and
`bind:isRendering` now fire around the flat progressive pass (`processed` counts rows).

### Shared loader replaces the spinner

|---|---|
| `--stv-spinner-duration` / `-size` / `-color` / `-track` | `--stv-loader-duration` / `--stv-loader-size` / `--stv-loader-color`; no track |
| `--stv-expand-spinner-size` / `-width` / `-track` / `-color` | `--stv-loader-inline-size` (size × 0.75) |
| — | `--stv-loader-icon`, `--stv-loader-rotate`, `--stv-loader-overlay-size` (size × 2) |

Each reads `--base-loader-*` first, so one page-wide setting reaches every Keenmate component.
The overlay content is the `loadingPlaceholder` snippet if you pass one, else the page-wide
`window.components.renderLoadingCallback`, else the default `.stv__loader`. The overlay is
`role="status"` with `labels.loading` as its name.

### Dark mode follows the core theme context

rc15 had ancestor selectors (`[data-theme="dark"] .stv__container`), so a light signal on
`<html>` could beat a nearer dark section. Now the tree reads one signal and writes it to
`.stv__container[data-context-theme]`: by default only `<html>` / `<body>` (`data-theme`,
`data-bs-theme`, `.dark` / `.light`). For a wrapper signal, say so:

```svelte
<div data-theme="dark">
  <Tree themeSource="closest" … />   <!-- or a selector / an Element -->
</div>
```

The per-instance `theme` prop still wins. `setThemeMode` / `getThemeMode` / `getThemeContext` /
`observeThemeContext` are exported and shared with the web-* components on the page.

### Logging moves to the core logger

Logging runs on the vendored Keenmate core logger (was `loglevel`). The namespace is `STV` (was
`LTREE`): categories `STV:INIT` / `DATA` / `RENDER` / `INDEX` / `DRAG` / `UI` and `STV:PERF`.
`window.components['svelte-treeview']` has core's registry shape (`version()`, `config`,
`logging`, `getInstances()`); its `perf` block is gone — use `enablePerfLogging()` /
`setPerfThreshold()`. See [the default level](#logging-default-level-is-warn).

## Behaviour changes

### Defaults follow web-treeview

| Prop | rc15 | rc16 | Keep rc15 |
|---|---|---|---|
| `expandLevel` | `2` | `0` (only roots) | `expandLevel={2}` |
| `shouldHandleKeyboardShortcuts` | `false` | `true` (Ctrl/Cmd+C/X/V, Delete, Esc) | `shouldHandleKeyboardShortcuts={false}` |
| `shouldAlignNodeIcons` | `false` | `true` (icon column reserved) | `shouldAlignNodeIcons={false}` |
| `nodeTitleOverflow` | `'wrap'` | `'ellipsis'` (fixed row height, which virtual scroll needs) | `nodeTitleOverflow="wrap"` |
| `scrollToPath` flash | on | off | `{ shouldHighlight: true }` |
| `indexerBatchSize` | `25` | `1000` (a cap per idle slot; batches are time-boxed) | `indexerBatchSize={25}` |

### Keyboard follows WAI-ARIA

**Enter** expands / collapses the focused node in every mode. **Space** toggles the selection:
the checkbox when checkboxes are shown, the focused node with `selectionMode: 'multiple'` (Enter
did that in rc15), and it **selects** the focused node in single mode without checkboxes (it
expanded / collapsed). Space never expands. Keyboard moves scroll instantly with
`block: 'nearest'` (were smooth and centred), so a held key never lags.

### Collapse is animated and returns a Promise

Rows an expand reveals fade and slide in; rows a collapse hides shrink and fade before the node
really collapses. `collapseNodes()` / `collapseAll()` return a Promise that settles after the
collapse applied, and `onNodeCollapse` / `onExpandedChange` fire then — not synchronously as in
rc15. Code that reads `expandedPaths` or the visible rows right after a collapse must `await`
it:

```ts
await tree.collapseAll();
console.log(tree.getVisibleFlatNodes().length);
```

Turn it off with `motion="none"` (or page-wide `window.components.motion = 'none'`), or just the
rows with `--stv-row-animation-duration: 0s`. OS reduced motion makes it instant.

### Logging default level is warn

rc15 logged nothing by default (`silent`); rc16 logs warnings and errors (`warn`, core's
default). Quiet it page-wide with `window.components.logging.disableLogging()`, or just this
component with `window.components['svelte-treeview'].logging.disableLogging()`.

### Sorting is numeric-aware

Siblings without an order value compare their display values with
`Intl.Collator(undefined, { numeric: true })` (was `localeCompare`), so `Item 2` sorts before
`Item 10`. One rule everywhere: `sortCallback` → `orderMember` → display value.

### Pasting into a node expands it

`pasteNodes(path)`, Ctrl+V and the menu's Paste with position `child` open a collapsed target
(expand events fire) and scroll the first pasted node in. `before` / `after` pastes are
unchanged.

### Silent selection no longer fires onFocusChange

`selectNode` / `selectNodes` / `selectAll` with `{ isSilent: true }` move the focus without
`onFocusChange` (it fired in the unpublished 5.0.0 — rc15 had no `onFocusChange`). Assigning
`selectedPaths` is silent too. Drive a detail pane from `onSelectionChange`, not from an
`$effect` on `bind:selectedPaths` — the bound value still changes on a silent select.

## New features

### Expand family and lazy loading

`bind:expandedPaths`, `onNodeExpand` / `onNodeCollapse`, `onExpandedChange` and
`beforeExpandCallback` — return `false` to keep a node closed, or a Promise to load its children
first (the toggle shows the loader, the row gets `aria-busy`):

```svelte
<Tree beforeExpandCallback={async (ctx) => {
  if (needsLoad(ctx.node)) ctx.controller.addBranch(ctx.path, await fetchChildren(ctx.path));
}} … />
```

`toggleNodeExpanded(path)` is new; `ExpandOptions { isExclusive, isSilent }` on every expand
method.

### Focus and tree-change events

`onFocusChange({ focusedNode })` fires for click, keyboard, `focusNode` / `clearFocus` and
removal. `onTreeChange()` fires once per mutation batch (add / insert / move / remove / update /
paste / drop / sort), after `nodes` was written back.

### Row animation

On by default, no on/off prop — `motion` is the one switch, as in every Keenmate component. The
new `motion` prop (`'auto' | 'none' | 'snappy' | 'smooth'`, written as `data-motion`) sets this
tree; a `data-motion` section or `window.components.motion` sets a region or the page.
`rowAnimationLimit` (default `50`, `0` = none) caps the rows animated per expand.
`--stv-row-animation-distance: 0` makes it a plain fade.

### Sorting control

`isSortingEnabled={false}` never auto-sorts: input order is kept, added nodes append, inserts /
moves / drops keep their exact position. `sortNodes(paths, options?)` sorts one level,
`sortAll(paths?, options?)` whole subtrees, with `compareCallback` / `direction` / `isSilent`.
With `orderMember`, a custom order rewrites the order values and fires `onNodesReorder` per
parent.

### Search status and a faster indexer

The indexer works in time-boxed idle slots: 55k nodes index in about 2 s (was about 125 s), and
`onIndexProgress({ processed, total, isComplete })` reports it. `searchResultLimit` (default
1000) replaces FlexSearch's silent 100-match cap; `onSearchStatusChange({ searchTerm,
matchCount, isLimited, limit, isIndexing })` and `controller.searchStatus` tell you when the list
was cut. Experimental `filterScope` / `filterDescendantDepth` / `shouldExpandFilterDescendants`
decide which descendants of a match stay visible.

### Element API on Tree

`<Tree>` exports what web-treeview's element has: `getSelectedNodes`, `isNodeSelected`,
`getVisibleFlatNodes`, `getTree`, `getNodeRef`, `openContextMenu(path, x, y)`,
`isNodeDropAllowed`, `duplicateNodes`, the clipboard methods and the `nav*` family (new
`navNext` / `navPrev`). Custom menu renderers get `controller.menuContext(node | null)`,
`menuItemDefaults`, `activateMenuItem` (runs the veto → `onClick` → built-in → `onAction` order),
`resolveMenuEntries` and `getMenuChildren`.

## Visible changes without a migration

- Indent per level: **16px** (was 8px), from `--base-tree-indent` (1.6 × rem). Old density:
  `--stv-indent-size: 8px`.
- Selection is a soft accent tint (10%) with no outline; focus is a 1px **inset** outline ring
  (rc15 had no default focus look); hover is a neutral tint, hidden under a selected row.
- `--selected-border` / `--selected-glow` presets are 1px inset rings (were a 2px border with
  padding that made the row jump, and an outer glow); `--selected-brackets` keeps its chevrons
  with checkboxes on. The row pill sits `--stv-checkbox-gap` (0.6rem) clear of the checkbox.
- Drop targets are green (`--base-drop-target-*`), no longer the accent tint.
- Standalone defaults are the base-css-variables contract's: dark surface slate `#1e293b` (was
  `#1a1a1a`), row pill radius 4px (was square), context menu at z-index 7500 (was 1000),
  tooltip at 9000 (was 10000).
- Transitions use four speeds (0.1 / 0.15 / 0.25 / 0.3s); 200ms transitions became 0.15s, and the
  drag-denied row tint fades in and holds instead of pulsing. Reduced motion sets them to 0s.
- The loader is the suite's mask shape, not a bordered ring.
- Tooltips, the drag ghost and the info popover take their shadow colour from
  `--base-shadow-color`.
- Disabled checkbox opacity 0.65 (was 0.6); disabled menu items 0.65 (was 0.5).

## Fixes

- A tree that started with a `searchTerm` showed "No results" forever.
- Search after removing nodes returned the wrong nodes; removed nodes stayed findable, and nodes
  added with `addNode` were never findable.
- Checking a node while filtered computed the cascade from the visible children only.
- Switching `checkboxMode` at runtime didn't update the rendered rows.
- Emoji / symbol icons from `iconMember` / `getIconCallback` rendered nothing.
- With `shouldTooltipFollowCursor`, a tooltip on a still pointer sat at the row's corner.
- The tooltip was narrower than web-treeview's under a page `border-box` reset.
- The empty-tree drop placeholder caused a horizontal scrollbar.
- A context menu opened from a button's `onclick` closed at once.
- Space toggled a copy of the focused node, so the row kept its old look.
- Assigning `selectedPaths` left the previous rows' selected markers on.
- A silent `expandNodes` / `collapseNodes` didn't show the change.
