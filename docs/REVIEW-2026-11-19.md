## 2. Naming (BlissFramework naming-conventions) — almost all ‖

The guideline's verb registry: Bliss (create update delete get search process map check validate verify
ensure generate parse copy send, is/has/can/should) + DOM (render handle dispatch attach/detach
mount/unmount observe compute position/anchor open/close show/hide toggle focus/blur commit reconcile
register/define destroy) + the public glossary (D-NC-13). **"apply" is never a method name; lookups are
`get*`, never `find*`; drag/drop are gesture-only; "restrain yourself".**

## 3. Duplication → generic helpers (the high-value refactors)

1. **One prop table** (L). Props live 4× in Tree.svelte (destructure defaults, `createTreeController` args, ~85 `$effect` mirrors, `update()` with 130 `if`s) + 3× in the controller (field defaults, constructor `??`, `updateProps`) + `nodeConfig` twice. Defaults already disagree: `shouldAlignNodeIcons` (nodeConfig `false`, everywhere else `true`), `shouldHandleKeyboardShortcuts` / `expandLevel` vs CLAUDE.md. → one `PROP_SPEC` / `DEFAULTS` table, constructor + `updateProps` iterate it, Tree runs one effect per runtime key, `update()` = `controller.updateProps`. ≈ −400 lines, fixes B5/B16/B17 by construction.
2. **One writer per state family** (M). Selection (replace / add / restore written ~8×, always followed by notify + mirror), checked (`_onCheckboxToggle` vs `_applyCheckboxState` — same cascade loop, bitten twice; three different filtered semantics), focus. → `_setSelection(paths, opts)`, one checkbox core, one `_setNodeFlag(path, key, value)` that writes real node + filtered copy. Fixes R1, R5, B21.
3. **Mutation bracket** (S). `_markNodesChanged(); … tick().then(() => { _skipInsertArray = false; _markNodesChanged(false) })` ×16 → `_mutate(run)`; give post-removal state reconciliation (B2) one home; probably drop `_skipInsertArray`.
4. **Clipboard / copy** (M). `copyNodes` vs `cutNodes` ~85 % identical; `pasteNodes` (280 lines) re-implements subtree-insert-with-skip that `copyNodeWithDescendants` already does right (→ fixes R2, B12); "leaf-aware child landing" copied verbatim; NodeRef / NodeTransformContext built 4× and they disagree on `source.siblings` for a top-level node.
5. **Drag** (M–L). HTML5 path (`dragOver` / `drop` / `dragLeave` have ZERO callers; `startDrag` / `dropAt` / `_onNodeDragEnd` only used by the custom-layout example) duplicates the pointer path (~350 lines); `_handleDrop` builds the manifest twice (→ B9); drop-position "allowed" check written 5 ways; mode check 4×; `_resetDragState` vs `_resetPointerState`.
6. **Tree walks / path helpers** (M). Segment walk ×5, ancestor-paths ×4+, self-or-descendant test ×6, descendant collection ×7, whole-tree walk ×9, find-parent-or-root ×9, set-children-order ×4, set-hasChildren ×9, `_rev++` ×43, paths → live nodes ×15, top-level-of-paths ×3 (`_topLevelOf` ≡ `_getTopLevelSelectedPaths`). → `helpers/ltree-helpers.ts` (`walkPath`, `ancestorPaths`, `isSelfOrDescendant`, `forEachDescendant`, `forEachNode`, `parentOf` against the REAL root → fixes R3, `bumpRev`, `getTopLevelPaths`). web-treeview's `ltree.ts` (path→node index, `nodeAt`, `detachChild`, `indexSubtree`) is the model.
7. **ltree insert** (M). Row → node + flag seeding copied 3× (`insertArray`, `addBranch` — "same logic as insertArray", `addNode`); `removeNode` ≈ `removeBranch(path,false)`; `replaceBranch` ≈ `removeBranch(path,true)`; order-value logic twice; `createLTree` takes 33 positional parameters → options object; search value resolved twice (indexer doesn't fall back to the callback).
8. **Menus / keyboard / popovers** (M). Built-in menu actions = 4 parallel switches → one `BUILT_INS` table; keyboard map + `beforeKeydownCallback` live in Tree.svelte (canvas re-implements them, without Delete / Cmd) → `controller.handleKeydown`; node click routing in Node.svelte (canvas re-implements) → controller; `nav*` = 10 copies of the index lookup; 5 hand-rolled floating-ui setups (ContextMenuItem / ContextMenuLevel submenu block byte-identical); ContextMenuLevel duplicates ContextMenuItem and names the id attribute differently.
9. **Tree.svelte** (S). Two identical `{#each}` row loops; dead `{:else}` branch; dead `treeBody` snippet prop; drag state reaches Node via props AND NodeConfig; Node re-resolves allowed drop positions per row (calls the user callback per mounted row).
